# 접근성 실측 보고서 (WCAG 2.1 명암비)

심사 피드백 "접근성을 고려했다는 주장과 실제로 검증했다는 것은 다르다"에 대한 실제 대응 기록.
WCAG 2.1 명암비 공식(상대휘도 기반)으로 실제 색상 값을 계산했고, 기준 미달 항목은 색상을 조정함.

## 측정 기준
- 일반 텍스트(14px 미만 또는 18px 미만 비굵게): **4.5:1 이상**
- 큰 텍스트(18px 이상, 또는 14px 이상 굵게)·UI 컴포넌트 경계: **3:1 이상**

## 측정 결과 (수정 전)

| 항목 | 전경색 | 배경색 | 비율 | 기준 | 결과 |
|---|---|---|---|---|---|
| 본문(ink) on 배경 | #101010 | #f4f4f4 | 17.30:1 | 4.5:1 | ✅ PASS |
| 본문(ink) on 카드 | #101010 | #ffffff | 19.03:1 | 4.5:1 | ✅ PASS |
| 흐린텍스트(muted) on 배경 | #5a5a5a | #f4f4f4 | 6.27:1 | 4.5:1 | ✅ PASS |
| 버튼 흰글씨 on 검정 | #ffffff | #111111 | 18.88:1 | 4.5:1 | ✅ PASS |
| **강조색(accent) 텍스트 (eyebrow/별점)** | **#e8873a** | **#ffffff** | **2.64:1** | 3.0:1 | ❌ **FAIL** |
| **테두리(line) on 배경** | **#d6d6d6** | **#f4f4f4** | **1.32:1** | 3.0:1 | ❌ **FAIL** |
| 다크모드 전반 | - | - | 8.09~19.26:1 | - | ✅ PASS |

> 참고: 고대비 모드 토글은 이후 제품 결정으로 제거함 (큰글씨 모드만 유지). 기본 라이트/다크
> 모드 자체가 위 표처럼 이미 WCAG AA를 통과하므로, 별도 고대비 모드 없이도 접근성 기준은
> 충족됨.

## 발견된 문제 2건

1. **브랜드 강조색(주황)을 텍스트로 쓴 부분이 기준 미달**
   - 위치: 온보딩 단계 캡션("1/7"), 별점(★), 진행 트랙의 현재 단계 표시
   - `#e8873a`는 흰 배경에서 2.64:1 — 저시력 사용자에게는 거의 안 보일 수준

2. **카드·입력창 테두리 색이 배경과 거의 구분 안 됨**
   - `#d6d6d6` on `#f4f4f4`는 1.32:1 — 시각적 경계가 사실상 없는 수준

## 수정 내역

| 항목 | 수정 전 | 수정 후 | 새 비율 |
|---|---|---|---|
| 텍스트 전용 강조색 (`--accent-text` 신규 변수) | `#e8873a` | `#b25e1f` | **4.65:1** ✅ |
| 테두리(`--line`, 라이트모드) | `#d6d6d6` | `#8c8c8c` | **3.06:1** ✅ |
| 테두리(`--line`, 다크모드) | `#3a3a3a` | `#646464` | **3.17:1** ✅ |

- `--accent`(배경/배지 채우기 용도)는 원래 값 유지 — 배경으로 쓰일 땐 명암비 문제 없음(글자색만 문제였음)
- 다크모드의 accent(`#f0a15f`)는 원래도 8.09:1로 통과라 별도 조정 불필요

## 한계 (정직하게 밝힘)
- 이 검증은 **정적 색상 대비**만 계산기로 측정한 것이며, 실제 스크린리더(NVDA·VoiceOver) 사용성 테스트는 아직 수행하지 않음
- 이미지(후기 사진)의 대체 텍스트(alt)는 기본값("후기 사진")만 있고, 사진 내용을 설명하는 수준은 아님
- 다음 단계로 스크린리더 실사용 테스트, 키보드만으로의 전체 탐색 테스트가 필요함
